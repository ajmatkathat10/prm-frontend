# ER Diagram — Project & Resource Management (PRM) Tool

## Overview

The Entity-Relationship (ER) Diagram defines the **document schema structure** for the PRM MongoDB database. It specifies every collection, its fields with their data types and constraints, and relationships — including cardinality and reference fields.

The schema is designed to:
- Enforce schema structure at the application/ODM level via Mongoose
- Maintain data history (soft deactivation/ended status instead of hard deletion)
- Support fast queries for dashboards, AI Skill Matcher, and the background scheduler

## Collections Reference

### `users`

The authentication and access control collection.

| Field | Type | Constraints | Description |
|---|---|---|---|
| `_id` | ObjectId | Primary Key | Unique object identifier |
| `username` | String | UNIQUE, REQUIRED | Login username |
| `email` | String | UNIQUE, REQUIRED | Login contact email |
| `passwordHash` | String | REQUIRED | Bcrypt hashed password |
| `role` | String | REQUIRED (enum: ADMIN, MANAGER, EMPLOYEE) | User role |
| `isActive` | Boolean | DEFAULT: true | Account active state |
| `forcePasswordChange` | Boolean | DEFAULT: true | Force pass change on first login |
| `createdAt` | Date | Autogenerated | Creation timestamp |
| `updatedAt` | Date | Autogenerated | Last updated timestamp |

---

### `employees`

The employee work profile collection.

| Field | Type | Constraints | Description |
|---|---|---|---|
| `_id` | ObjectId | Primary Key | Unique identifier |
| `userId` | ObjectId | REQUIRED, UNIQUE, ref: users | Profile owner login link |
| `managerId` | ObjectId | ref: users, nullable | Assigned manager link |
| `fullName` | String | REQUIRED | Display work name |
| `email` | String | REQUIRED | Work email address |
| `department` | String | REQUIRED | e.g. Frontend, Backend, QA |
| `designation` | String | REQUIRED | Job title |
| `status` | String | REQUIRED (enum: BENCH, ALLOCATED, INACTIVE) | Computed resource status |
| `isActive` | Boolean | DEFAULT: true | Active profile status |
| `skills` | Array | Contains IEmployeeSkill | Embedded skill array |
| `createdAt` | Date | Autogenerated | Creation timestamp |
| `updatedAt` | Date | Autogenerated | Last updated timestamp |

| Field | Type | Constraints | Description |
|---|---|---|---|

## Relationship Summary

| Relationship | Cardinality | Connection | Description |
|---|---|---|---|
| `users` → `employees` | 1 : 1 | via `userId` | A User links to exactly one Employee profile |
| `users` → `projects` | 1 : M | via `managerId` | Managers manage projects |
| `employees` → `IEmployeeSkill` | 1 : M | embedded array | Employees contain embedded skills |
| `skills` → `IEmployeeSkill` | 1 : M | via `skillId` | Skills are referenced in employee skills |
| `employees` → `allocations` | 1 : M | via `employeeId` | Employees have active allocations |
| `projects` → `allocations` | 1 : M | via `projectId` | Projects have active allocations |
| `employees` → `timesheets` | 1 : M | via `employeeId` | Employees submit weekly timesheets |
| `timesheets` → `ITimesheetEntry` | 1 : M | embedded array | Timesheets contain entries |
| `projects` → `ITimesheetEntry` | 1 : M | via `projectId` | Entries link hours to projects |
| `projects` → `IMilestone` | 1 : M | embedded array | Projects contain milestones |

## MongoDB Indexes

To optimize performance across queries, the following MongoDB indexes are created:

```javascript
// Compound unique index for timesheets submission enforcement
db.timesheets.createIndex({ employeeId: 1, weekStart: 1 }, { unique: true });

// Index for allocations dashboard queries
db.allocations.createIndex({ employeeId: 1, status: 1, fromDate: 1, toDate: 1 });
db.allocations.createIndex({ projectId: 1, status: 1 });

// Index on employees manager scoping
db.employees.createIndex({ managerId: 1 });

// Index on projects management
db.projects.createIndex({ managerId: 1, status: 1 });
```
